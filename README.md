# 拼豆图纸生成器

一个在浏览器本地完成图纸计算的拼豆图纸工具。相册图片不上传服务器；原图、设置和当前图纸会自动存入当前浏览器的 IndexedDB，首页可恢复最近一份草稿。清除网站数据会移除草稿，跨浏览器、跨电脑请保存 `.perlerproj` 工程文件。链接图片仅经后端临时转发，导入后同样参与本机草稿保存。

> 项目使用 MARD 标准 221 色的屏幕近似色卡（A、B、C、D、E、F、G、H、M 系列）。显示颜色不等同于实体豆的官方测量值，购买材料请按色号并以实体色卡为准。

## 安装与运行

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

构建生产版本：

```bash
npm run build
```

本地预览生产版本：

```bash
npm run preview
```

运行算法测试：

```bash
npm test
```

## 当前功能

- 连续画笔、橡皮擦和四向连通区域填色；快拖经过的格子会自动补齐，一笔只记一次撤销；触屏双指缩放和取消手势会撤回未提交的一笔
- 画笔与橡皮擦在制作图中工作，进入工具时自动放大；快捷键 B 画笔、E 橡皮擦、G 区域填色、V 移动、S 选格换色、I 吸管取色、X 框选删除
- 吸管从图纸上取色作为画笔色；框选删除拖框把整片豆子改为留白；多选后可一键删除
- 制作图显示开关：网格、色号、圆豆预览、镜像查看（只影响屏幕显示，不影响导出）
- 合并零散色号：按占比阈值把用量很少的颜色并入最相近的颜色
- 编辑记录面板：每一步带名称和改动格数，点记录在图纸上框出改动的格子，可撤回到任意一步之前，或一键恢复到刚生成的样子（最多 50 步）
- 1:1 实物大小打印 PDF：可选 2.6mm / 5mm 豆，自动分页并选择纵向或横向，每页带 5cm 校准尺，附色号图例与用量
- 我的图纸：每份图纸单独自动保存在本机浏览器，可随时切换、删除，最多保留最近 30 份（旧版单份草稿会自动迁移）
- 智能推荐：上传后分析背景、黑色线稿和颜色数量，推荐颜色效果与颜色上限，一键套用
- 文字转图纸：系统黑体，加随网站打包、按需下载的开源字体（Fusion Pixel 12/8 点阵字、站酷庆科黄油体、站酷快乐体、霞鹜文楷），手机和电脑效果一致；点阵字字高为字模格数的整数倍，每个字模像素正好一颗豆；其他字体低于可读字高时自动调高并说明。可调字距、行距、对齐；纯色字、描边字、云朵字、贴纸字、空心字、彩虹描边六种样式，12 套配色和彩虹色全部是 MARD 真实色号；生日祝福、名字牌、迷你钥匙扣等一键模板
- 空白画布：首页选好格数（29/52/58/104 或自定义），直接进入画笔从零画像素画
- 用豆清单中点一种颜色后，可把这个色号整体换成另一个色号（家里没有的色号一键替换）
- 可勾选已有 MARD 色号、批量录入色号、从当前图纸用色建立个人色板，并在本机保存最多12套命名色板；开启后同时限制生成、画笔和换色，颜色数量上限仍独立生效
- 已有色号随工程与草稿保存；有序模式缺少 H7 时使用可用色板中的深色画轮廓，绝不额外加入缺少的色号
- 首页展示真实原图与算法生成图纸，支持一键试做 Q版人物示例（按卡通 / Q版模式生成）；首页单独说明链接导入、防盗水印、分色定位图、卡通线稿和本地处理这几项特色
- 生成后切换到电脑端设置／画布／用豆三栏工作区；手机端通过底部三个面板切换
- 原图、编辑设置、留白蒙版和图纸自动保存为本机草稿，刷新后可继续；保存失败有状态提示与重试入口
- 可见的撤销与重做按钮；Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Shift+Z 或 Ctrl+Y 重做，支持改色和尺寸调整，最多20步；新编辑会清空重做分支
- 工程文件保存与打开，包含原图、设置、图纸及留白蒙版，兼容旧版工程文件
- JPG、PNG、WebP 点击/相册选择和拖拽上传
- 支持粘贴抖音图文或小红书图文分享链接，读取多图后由用户选择一张导入；视频作品会明确提示不支持
- 首页可直接上传已有网格图纸截图并自动识别横纵格数、排除坐标栏、逐格恢复底色；检测到规则色块图例时仅在图例色卡内匹配，没有图例时自动回退到完整色卡
- 图纸生成并改色后可直接按目标宽高居中裁掉网格边缘，不重新识别；奇数差值由左侧、上侧多裁一格，并支持撤销
- 触摸友好的自由、正方形、竖版、横版和图纸比例裁剪
- 左右旋转、水平翻转、恢复原图、重新上传
- 50×50、64×64、70×70、90×90、104×104、70×104和自定义尺寸
- 自动识别图片实际需要的颜色，用户只设置15、24、48、96或221色上限
- 按图片类型选择生成模式：照片、插画 / 海报、卡通 / Q版、像素画 / Logo；智能推荐直接给出类型。像素画模式会识别放大过的像素画网格（支持非整数倍放大和裁剪），一个像素块一颗豆还原，透明背景自动留白；卡通 / Q版模式有序模式按整格平均色取色，主体外圈一格 H7 轮廓，原图线稿只取一格宽的中脊（彩色深线保留本色），合并近似色并温和整理碎色，轮廓外自动留白
- Web Worker 本地色卡匹配、限色和孤立点整理
- 效果图与带清晰编号、坐标、网格、5×5粗辅助线、色卡和统计的制作图
- 单指拖动、双指缩放、滚轮缩放、双击放大/恢复和全屏查看
- 真实用豆清单、颜色高亮、展开/收起和复制
- 制作图支持点击单格更换颜色；可换成纯白留白，留白不显示色号且不计入用豆统计
- 桌面端可在制作图格子上点击鼠标右键，立即将该格改为纯白留白
- 独立离屏 Canvas 生成高分辨率效果图 PNG 与高清制作图 PNG
- 导出图使用缩略图中也能辨认的“@小石豆图”大号水印，并大幅标注“原创作品 · 禁止盗用”
- 可开启或关闭铺满式斜向防盗水印，默认文案为“@小红薯 小石豆图”，支持导出前修改
- 镜像制作图左上角显示醒目的“镜像图”标识，文字和色号保持正向
- 一键导出全部分色定位图时，每种颜色同时生成正向版和镜像版，在 ZIP 内分别放入“非镜像”和“镜像”文件夹
- 根据设备内存和图纸大小自动控制导出分辨率，失败时自动降低一级重试

自动识别为纯白背景且不显示 H2 色号的格子，以及手动设置的纯白留白，都不代表实体豆，因此不会计入颜色清单和总豆数；H2 只统计主体中实际显示 H2 色号的白色豆。

## 部署

运行 `npm run build` 后，网页文件在 `dist/client/`。图片转图纸、图纸识别、文字转图纸、空白画布和导出都在浏览器本地完成，只需要静态托管。

“链接导入”需要后端临时转发抖音、小红书的图片，接口为 `/api/resolve-link` 和 `/api/link-image`：

- Vercel：按 `vercel.json` 部署，`api/` 目录会作为函数运行。
- Cloudflare：`worker/index.js` 处理这两个接口，其余请求交给静态资源。
- 只用普通静态服务器（GitHub Pages 等）时，链接导入不可用，其他功能不受影响。

### 腾讯云 EdgeOne Makers 静态部署

保留原有 `npm run build`，供现有部署环境使用。EdgeOne 请使用独立命令 `npm run build:edgeone`，它只执行 `vite build`，不运行 Sites 专用的 `scripts/prepare-sites-build.mjs`，因此不要求存在未提交到仓库的 `.openai/hosting.json`。

在 EdgeOne 的项目构建设置中填写：

| 配置项 | 值 |
| --- | --- |
| 项目根目录 | 仓库根目录（`package.json` 所在目录） |
| 安装命令 | `npm ci --include=dev` |
| 构建命令 | `npm run build:edgeone` |
| 静态网站输出目录 | `dist/client` |
| Node.js 版本 | `22.21.1` 或满足依赖要求的更新版本（Vite 要求 `^20.19.0` 或 `>=22.12.0`，Wrangler 要求 `>=22.0.0`） |

仓库根目录的 `edgeone.json` 已保存上述安装、构建、输出目录和 Node.js 设置，并为现有功能页配置精确的内部重写。EdgeOne 会优先使用该文件中的配置，详见 [EdgeOne 配置说明](https://pages.edgeone.ai/zh/document/edgeone-json)。其他部署平台继续使用各自配置。

当前 Vite 配置包含 Cloudflare 插件，因此客户端产物位于 `dist/client/`，不是默认的 `dist/`：

```text
dist/
├── client/
│   ├── index.html          # 静态网站入口
│   ├── photo.html          # 各功能页面，另有 recover/text/link/library/editor.html
│   ├── favicon.svg
│   ├── robots.txt
│   └── assets/             # 带哈希的 JS、CSS、示例图片及字体分片
└── perler_pattern_web/     # Cloudflare Worker 构建产物，不是 EdgeOne 静态输出目录
```

整个 `dist/client` 应作为网站根目录发布，浏览器访问的是 `/index.html`、`/assets/...`，URL 中不要添加 `/dist/client`。现有 `base: '/'` 适用于域名根路径部署，不适用于挂载到 `/某个子目录/`。

- 图片、JS、CSS 和按需加载的字体均由 Vite 处理资源路径，随 `dist/client` 一起发布，无需配置外部字体 CDN。
- 图纸算法的 Web Worker 使用 `new Worker(new URL(..., import.meta.url))`，由 Vite 打包处理，不需要服务端 Worker 运行环境；它与 `dist/perler_pattern_web` 的 Cloudflare Worker 是两回事。
- PNG、PDF、ZIP 和工程文件在浏览器中生成并下载；PDF 不依赖服务器接口或外部 PDF 模板。
- 页面使用 `/photo`、`/text` 等无扩展名路径；`edgeone.json` 将六个现有功能路径分别重写到对应的 `.html`，不拦截 `/assets/` 或 `/api/`。部署后应确认功能页可以直接打开和刷新。
- 这套配置仅部署静态网站，不会把 `api/` 的 Vercel 函数或 `worker/index.js` 自动转换成 EdgeOne 函数。“链接导入”的 `/api/resolve-link`、`/api/link-image` 需另行接入后端；相关源码保留，其他本地处理功能不依赖这两个接口。

本地验证命令：`npm run build:edgeone`。可选设置环境变量 `SITE_URL=https://你的域名` 后再构建，以生成网站地图和 canonical 地址。

### 页面地址与搜索收录

各功能是独立路径：`/`、`/photo`、`/recover`、`/text`、`/link`、`/library`、`/editor`，路径、标题和描述集中在 `src/state/pages.js`。构建时每个页面生成一份 HTML（如 `photo.html`），带各自的 `<title>`、`description` 和顶部标题；`/library`、`/editor` 依赖本机数据，标记为不收录。旧版 `#photo` 这类地址会自动跳到对应路径。

构建时设置站点地址可额外生成 `sitemap.xml` 和 canonical 地址：

```bash
SITE_URL=https://你的域名 npm run build
```

托管需要把 `/photo` 对应到 `photo.html`：Vercel 已在 `vercel.json` 开启 `cleanUrls`；Cloudflare 的静态资源默认如此，`worker/index.js` 另外兜底，并把 `/photo/`、`/photo.html` 301 跳到 `/photo`。

文字转图纸的开源字体会随构建拆成很多小分片（`dist/client` 约 19MB），访问时只下载当前文字用到的分片。

## 主要目录

- `src/image/`：图片解码、裁剪、旋转和缩放
- `src/color/`：RGB/XYZ/Lab 转换与色卡匹配
- `src/workers/`：耗时图纸计算
- `src/canvas/`：效果图、制作图和触控视口
- `src/export/`：离屏 Canvas PNG、1:1 打印 PDF 与分色定位图导出
- `src/text/`：文字转图纸的字体、排版与描边样式
- `src/state/`：统一状态和尺寸配置
- `src/data/palettes/`：MARD 221 屏幕近似色卡 JSON
